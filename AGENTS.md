# amops project instructions

For each task, read `docs/rules.md` and the applicable nested `AGENTS.md` before editing.
For product or UI work, also read `docs/design.md` and `docs/landing_page_blueprint.md`.
Use `docs/executive_summary.md` and `docs/nexus_implement_plan.md` for product intent,
and `docs/architecture.md` for architectural boundaries.

- Follow the user's current scope. Preserve unrelated changes and intentional deletions.
- Inspect existing components, hooks, utilities, and tokens before creating equivalents.
- Share repeated UI and data; avoid duplicated desktop/mobile implementations.
- `docs/design.md` owns colors, typography, themes, and motion rules. Use shared tokens.
- `docs/landing_page_blueprint.md` owns the landing story and its acceptance checks.
- Old memory entries and completed task boxes are historical evidence, not proof of current release status.
- Verify marketed capabilities against the current implementation; label previews and planned features.
- Record material decisions and verification in `docs/memory.md`; keep task status truthful.
- For frontend code, follow `frontend/AGENTS.md`, including its installed Next.js documentation requirement.
